## 2. 关键唯一索引（不变量落点）

| 不变量 | 表.唯一索引 |
|---|---|
| I1 事件唯一（R3 双保险） | usage_event: `uk(ingest_system, event_id)`；指纹兜底 `uk(tenant_id, product_id, biz_no)`（biz_no NULL 不参与） |
| I2 抵扣链顺序 | 服务层固定编排（非约束） |
| I3 余额/余量不超扣 | balance_account 行锁 + version 乐观锁；扣减 SQL 带 `remaining >= n` 条件 |
| I4 应付=原额+生效调整 | bill: `uk(tenant_id, period)` + `uk(bill_no)`；生效调整单由服务层回写 adjust_cents |
| I5 库存不超卖 | goods.total_stock/sold 权威值 + Redis Lua 预扣 + stock_log 留痕对账 |
| I6 初审≠复审 | adjustment_order 存 review1_by/review2_by，服务层强制校验 |
| 租户串行 | balance_account: `uk(tenant_id)` 单行 + `SELECT … FOR UPDATE` |
| 重跑幂等（R42） | daily_recon: `uk(recon_date)`；bill: `uk(tenant_id, period)`；task_instance: `uk(task_name, biz_key)` |
| Key 接入校验 | api_key: `uk(key_hash)`（SHA-256 散列匹配，ET4） |

> 分表表（usage_event 等）唯一索引仅**分表内**生效：全局唯一由 Redis 判重前置（TTL≥48h）承担主责，库内唯一索引兜底同表重试场景——该边界为规范 5.3 的既定口径，写入压测验证项。

## 3. ShardingSphere 分表与归档策略

| 逻辑表 | 物理分表 | 分片键 | 保留期 | 归档 |
|---|---|---|---|---|
| usage_event | usage_event_$yyyyMM | arrive_time | 1 年 | 整表归档后 DROP（XXL-Job + 留痕 B9） |
| deduction_record / deduction_item | 同后缀 | created_at | 在线 1 年 | **归档转储（不 DROP）保留 ≥3 年**（评审 P-1 对齐 requirements 第 8 章） |
| account_transaction | 同后缀 | created_at | 在线 1 年 | **归档转储（不 DROP）保留 ≥3 年**（同上） |
| audit_log | 同后缀 | created_at | 1 年 | 整表归档后 DROP（留痕 B9） |

- 分表由部署脚本按年预建（`deploy/init/`），示例见 schema-billing.sql 注释；
- 账单/调整单/抵扣汇总**不分表不删除**（≥3 年）；
- 查询面：控制台明细检索走 ES（第 7 章），精确回查可指定时间范围回落 MySQL。

## 4. 金额与精度落地（3.9 → 存储映射）

| 场景 | 字段 | 类型 | 口径 |
|---|---|---|---|
| 余额账户 | balance_cents | BIGINT 分 | 唯一权威余额；变动写 account_transaction |
| 逐笔计费 | usage_event.cost_amount | DECIMAL(20,6) 元 | 逐笔 4 位小数 |
| 抵扣流水 | deduction_record/item.amount | DECIMAL(20,6) 元 | 各抵扣源 4 位小数 |
| 日切汇总 | daily_snapshot.cost_cents | BIGINT 分 | 当日事件费用合并后 HALF_UP 入账 |
| 抵扣入账 | account_transaction.amount_cents | BIGINT 分 | **同一事件先合并总费用、再 HALF_UP 舍入到分**（ET1） |
| 账单 | original/adjust/payable_cents | BIGINT 分 | Σ逐笔舍入 + Σ生效调整（I4） |
| 单价 | price_item.price | DECIMAL(16,6) 元 | 最小 0.0001 元 |

## 5. Redis Key 规划

| Key | 用途 | TTL |
|---|---|---|
| `meter:idem:{system}:{eventId}` | 事件判重前置，存首次受理结果摘要 | 48h |
| `meter:fp:{tenantId}:{productId}:{bizNo}` | 业务指纹兜底判重 | 48h |
| `meter:suspend:{tenantId}` | 停服状态（normal/warning/suspended），ingest 拒收依据（P6） | 无（随余额变动更新） |
| `meter:balance:{tenantId}` | 余额读缓存（写穿透更新） | 60s |
| `equity:stock:{goodsId}` | 抢购库存（Lua 原子预扣，AD-T4） | 无 |
| `equity:bought:{goodsId}:{tenantId}` | 每人已购计数（含待支付） | 无 |
| `lock:{bizKey}` | Redisson 分布式锁（任务防重等） | 随锁 |

## 6. ES 索引设计（查询面，非账务权威）

| 索引 | 用途 | 关键字段 |
|---|---|---|
| `metering-events-yyyy.MM` | 消费明细检索（02 §1.4） | 事件ID(kw)、tenant_id、dept_name、product、metrics 摘要(text)、version、arrive_time(date)、cost、status |
| `audit-yyyy.MM` | 审计日志检索（5.10） | actor/role/action/target/scope/result/sensitive/created_at |

- 同步方式：**MQ 异步双写**（计费完成/审计事件 → 消费写入 ES，秒级延迟）；Canal 订阅 binlog 为备选（DT 后续评估）；
- 允许 ES 与 MySQL 短暂不一致，对账任务校平（R-10）。

## 7. RocketMQ 主题契约（落 `meterflow-common/event/`，04 阶段定义代码级契约）

| 主题 | 生产者 → 消费者 | payload 要点 | 幂等键 |
|---|---|---|---|
| T_BILLING_COMPLETED | billing → finance / platform / ES | 事件ID、租户、费用、抵扣链摘要 | eventId |
| T_BALANCE_CHANGED | billing → finance | 租户、变动前后余额、停服阶段 | 事务流水ID |
| T_ORDER_PAID | equity → billing | orderNo、租户、商品、数量、支付时刻 | orderNo |
| T_AUDIT_LOG | 各服务 → platform（入 ES） | 审计字段（第 6 章索引） | 审计ID |
| T_ADJUSTMENT_EFFECTED | finance → billing / platform | 调整单号、类型、金额、目标账单 | adjNo |
| T_DISPUTE_RESOLVED | finance → platform | 工单号、补偿结果 | disputeNo |
| T_BILL_LIFECYCLE | finance → platform | billNo、事件（issued/confirmed/settled）→ 站内通知 | billNo+事件（评审 P-2 补充） |
| T_DISPUTE_LIFECYCLE | finance → platform | disputeNo、事件（accepted/resolved）→ 站内通知 | disputeNo+事件（评审 P-2 补充） |

消费方一律幂等消费（唯一键 + 状态机校验）；投递语义 = 至少一次。

## 8. 表间关联与删除策略

- **关联**：事件 1:1 抵扣流水 1:N 来源明细（event_id/record_id）；账单 1:N 分段/部门小计/生效调整单（bill_no）；订单 1:1 支付流水 → 1:N 实例（order_no）；差错/争议 0..1 调整单（related_no）。跨库一律**逻辑关联（业务号）**，无外键约束；
- **删除策略**：账务/计费/审计数据**无物理 DELETE**（P2）；成员/部门/Key 状态迁移；分表到期整表归档 DROP（XXL-Job 执行、审计留痕 B9）；资源包实例到期**状态迁移**（expired，余量清零留痕 R33/R34）。

## 11. 裁决结果（2026-11-03，交互确认）

| 编号 | 结论 |
|---|---|
| ET1 | 同一事件多指标**先合并总费用再 HALF_UP 到分**入账【确认】 |
| ET2 | 实例余量 = DECIMAL(20,4) 原生单位 + `unit` 字段（Token/次/元），元类以分值折算【确认】 |
| ET3 | 分表到期归档 DROP 由 XXL-Job **自动执行**并审计留痕【确认】 |
| ET4 | api_key **hash 存储**（SHA-256，明文仅创建时一次性返回；非推荐项，用户裁决）——api_key 表已改为 `key_hash CHAR(64)` + `uk(key_hash)`【确认】 |
