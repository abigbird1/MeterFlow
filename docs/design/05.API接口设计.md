## 1. 规范摘要（全文见 meterflow.md #7）

路径前缀四组：`/ingest/**`（事件上报）、`/t/**`（租户端）、`/a/**`（管理后台）、`/feign/**`（服务间）；统一响应 `{code, message, data}`，`code="00000"` 成功；错误码分段 `GWY-/PLT-/BIL-/EQY-/FIN-`+4 位数字；HTTP 401/403/429 语义（停服=403+`METER_SUSPENDED`）；鉴权 Bearer token（Sa-Token）+ `@SaCheckPermission("权限点")`；事件上报用 `X-API-Key`；金额出参 `*_cents`（BIGINT 分），过程金额字符串；分页 `pageNum/pageSize`。

## 2. 通用定义

### 2.1 统一响应

```json
{ "code": "00000", "message": "成功", "data": { } }
```

### 2.2 错误码（关键枚举，完整枚举在开发阶段随代码落地）

| code | HTTP | 说明 | 规则 |
|---|---|---|---|
| GWY-0401 | 401 | 令牌无效/过期 | — |
| GWY-0403 | 403 | 权限点不足 | 6.1/6.2 |
| GWY-0429 | 429 | 触发限流（Sentinel） | 1.4 |
| BIL-0401 | 401 | API Key 无效/禁用 | 4.6 |
| **BIL-4031** | **403** | **停服拒收（message 含 METER_SUSPENDED）** | **R8** |
| BIL-4002 | 200→受理失败 | 业务指纹冲突（Redis 兜底触发，罕见） | R3 |
| BIL-4003 | 200 | 迟到事件已转人工差错队列 | R6 |
| EQY-4001 | 200 | 库存不足（已售罄） | R31 |
| EQY-4002 | 200 | 超出每人限购 | R31 |
| EQY-4003 | 200 | 订单已关闭/超时，支付拒绝 | R43 |
| EQY-4004 | 200 | 超出开售窗口 | R31 |
| FIN-4001 | 200 | 账单状态不允许该操作 | 第 7 章 |
| FIN-4002 | 200 | 当前账单状态不可发起争议 | R44 |
| FIN-4003 | 200 | 调整单审批人同岗（初审=复审） | I6 |
| PLT-4001 | 200 | 邮箱已被注册/占用 | — |

### 2.3 通用约定

金额：确定性金额 `*_cents`（BIGINT 分）；过程金额字符串（如 `"0.0214"`）。时间：`yyyy-MM-dd HH:mm:ss`。分页：`pageNum/pageSize`（默认 1/20，≤100），响应 `data={list,total,pageNum,pageSize}`。鉴权：`Authorization: Bearer <token>`；事件上报 `X-API-Key`。写接口可选 `Idempotency-Key` 头。

## 4. 事件上报（billing-service，1 个，热路径）

### 4.1 POST /ingest/events 【核心接口】

- **鉴权**：`X-API-Key`（platform 缓存/Feign 兜底校验，ET4 hash 匹配）；**限流**：Sentinel 500 TPS 口径；**幂等**：R4。
- **入参**：

```json
{
  "ingestSystem": "ai-gateway",
  "eventId": "evt-9f81c2",                        // 上报方全局唯一（R3）
  "bizNo": "req-20261103-0001",                   // 业务流水号（指纹兜底，可空）
  "productId": 1001,
  "eventTime": "2026-11-03 10:00:00",             // 参考时间（计费以到达时间为准 R5）
  "metrics": [                                    // 复合事件多指标（R1），原生单位
    { "key": "calls",  "qty": 1200 },
    { "key": "in_tok", "qty": 4800000 },
    { "key": "out_tok", "qty": 2600000 }
  ]
}
```

- **出参（新事件）**：

```json
{ "status": "accepted", "costAmount": "13.6160",
  "chain": [ {"source":"赠送免费额度","amount":"0.0720"}, {"source":"内置月度额度","amount":"7.1416"},
             {"source":"资源包(指定包优先)","amount":"15.5280"}, {"source":"余额","amount":"13.6160"} ],
  "balanceCents": -5112, "stage": "warning" }
```

- **出参（重复）**：`{"status":"dup","originEventId":...,"costAmount":"<首次结果>"}`（R4，HTTP 200）。
- **错误**：BIL-0401 / BIL-4031（HTTP 403）/ BIL-4002 / BIL-4003。

### 4.2 POST /ingest/events/batch（批量上报，AF1 裁决新增）

- **入参**：`{"events": [ <同 4.1 入参对象>, ... ]}`，单次 ≤ 500 条；
- **出参**：`{"results": [ {"eventId":..., "status":"accepted"\|"dup"\|"rejected", "code":..., "costAmount":..., "chain":[...]}, ... ]}`（逐条幂等，顺序与请求一致）；
- **口径**：逐条独立判重与计费（复用 4.1 链路）；任一条失败不影响其余；HTTP 200；总耗时目标 ≤ 3s（压测验证项）。

### 6.7 核心接口详表（示例级出入参）

**① POST /a/products/{productId}/price-versions（调价）**
- 入参：`{items:[{metricKey:"in_tok", price:0.0018}], note:"输入Token降价"}`
- 出参：`{versionNo:"v3", effectiveAt:"2026-11-03 10:05:00"}`
- 规则：R11 即时生效、账期内分段；审计留痕。

**② POST /a/recon/errors/{errNo}/adjustments（发起冲正）**
- 入参：`{adjType:"adjust_red", amountCents:2840, reason:"资源包重复扣减"}`
- 出参：`{adjNo:"ADJ20261103-01", stage:"review1"}`
- 规则：R28 不改原始单据；差错单→correcting。

**③ POST /a/adjustments/{adjNo}/review（审批）**
- 入参：`{stage:1, result:"pass"}`
- 出参：`{stage:"review2"}` / `{stage:"done", effectNote:"B2026-10 应付已更新"}`
- 校验：岗位（review1=审核员、review2=财务/运营按类型）+ 初审≠复审（I6）→ FIN-4003。

**④ POST /a/disputes/{disputeNo}/proxy-query（代查）**
- 入参：`{scope:"2026-10 账单及消费明细"}`
- 出参：`{billSummary:{...}, eventSamples:[...], auditNo:"AUD..."}`
- 规则：R37 四要素强制入审计；返回内容与原型一致。
