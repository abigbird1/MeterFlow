## 2. 系统拓扑

| 服务 | 端口 | 职责（领域） | 依赖 |
|---|---|---|---|
| meterflow-gateway | 8080 | 统一入口：路由 / JWT 校验 / Sentinel 限流 / 静态托管 | 全部服务 |
| meterflow-platform | 8081 | 认证（Sa-Token）/ 租户 / 组织 / API Key / 通知 / 审计 | MySQL, Redis |
| meterflow-billing | 8082 | 计量计费（ingest）/ 钱包余额 / 总览 / 导出 / 产品计价 | MySQL, Redis, platform |
| meterflow-equity | 8083 | 商品 / 订单（锁库存）/ 资源包实例（outbox 发放） | MySQL, Redis, billing |
| meterflow-finance | 8084 | 账单 / 对账 / 冲正审批 / 争议 / 催缴 / 定时任务 | MySQL, billing, platform |

- 网关路由表见 `meterflow-gateway/application.yml`（/ingest → billing，/t/**、/a/** 按域分发）。
- 服务间同步调用走 OpenFeign（`/feign/**` facade 层，网关不暴露）。
- S4 实例发放走 outbox + relay（最终一致，失败自动重试）。

## 3. 快速启动

```bash
# 1) 中间件（MySQL 首次启动自动执行 scripts/sql 建表；全量约 10GB 内存，R-9）
cd deploy && docker compose up -d        # mysql/redis/nacos/sentinel-dashboard/rocketmq/es 可按需启停

# 2) 后端（本机 JDK 17；构建）
cd server && mvn -DskipTests install
# 依次运行 platform/billing/equity/finance/gateway（jar 在各模块 target/，或 mvn spring-boot:run）

# 3) 访问
http://localhost:8080                    # 一体化：前端 + API 单端口
# 前端开发模式（可选）：cd web && npm install && npm run dev   # 5173 → 代理 8080

# 前端改动后同步到网关：
bash scripts/sync-web-to-gateway.sh      # 构建 + 拷贝 dist → gateway static，重打包网关
```

### 4.2 性能基线（5 万事件实测，README 同步记录）

突发 ~900 QPS 打 /ingest → 超阈值部分返回 `429 + {"code":"GWY-0429"}`；低速率无误伤；e2e T32 固化。

## 7. 运行时行为

| 机制 | 行为 |
|---|---|
| 日切对账 | 每日 00:05 对上一业务日（finance @Scheduled，可传 date 手动补跑），按日幂等（FIN-4005）；三口径比对生成差错单（R26/R27） |
| 月末全员出账 | 每月最后一天 23:30（28-31 cron + 次日=1 日守卫），对有用量租户逐户出账，uk(tenant,period) 幂等；出账后自动执行账期全量复核（R26），摘要随接口返回 |
| 争议 SLA 升级 | 每 5 分钟扫描超期 pending/processing 工单 → 标记 + 站内通知（R36） |
| Key 用量统计 | usage_event 记录上报 Key；/t/keys/stats 本月聚合（SQL GROUP BY，规范 #5.9） |
| 消费异常检测 | 每日 00:15 对昨日消费 vs 前 7 日日均（>5 倍且 >10 元）→ 站内提醒；/feign/billing/anomaly-check 可手动触发 |
| 部门消费统计 | /t/depts/stats 本月按部门聚合；组织页展示（成员部门隔离沿用） |
| 月度预算告警 | 每小时第 10 分扫描本期预算：消费 ≥80%/≥100% 发站内告警（标记位防重发，100% 覆盖 80% 位）；设置仅租户管理员，调整预算重置标记 |
| S4 实例发放 | 支付成功 → outbox → relay（2s 轮询）→ billing 发放，失败重试 |
| 登录失败锁定 | 同邮箱连续 5 次失败锁 10 分钟；成功即清零（内存实现，E2） |
| 审计留痕 | 敏感操作注解拦截 → audit_log（四要素；P5） |

## 9. 故障排查 FAQ

| 现象 | 原因与处置 |
|---|---|
| `Unable to rename *.jar` 构建失败 | jar 被运行中进程锁定：按端口 `taskkill //F //PID` 后重试 |
| 登录提示「失败次数过多已临时锁定」 | E2 锁定（连续 5 次失败/10 分钟）：重启 platform 或等待；登录成功即清零 |
| ingest 返回 429 GWY-0429 | Sentinel 500 TPS 兜底生效：正常限流，退避重试 |
| 抢购/账单等业务操作报 500 | 确认 equity/finance 为最新构建（已修复 equity 缺全局异常处理器的问题） |
| Windows Git Bash curl 中文 JSON 报 UTF-8 错 | shell 以 GBK 发送：测试中文场景改走浏览器/UTF-8 客户端 |
| T32 突发后紧接的用例被 429 | 限流窗口 1s 滑动：脚本已内置 sleep 2 |
| 站内通知未收到 | 确认 finance 使用 NotifyClient（platform-url:8081）；billing 无 /feign/notify（历史坑） |
