### 1.2 架构原则（业务级）

| # | 原则 | 来源 |
|---|---|---|
| P1 | **实时逐笔计费是唯一热路径**：受理→判重→计价→抵扣在同一同步链内完成；其余能力（对账、出账、到期、催缴、提醒）均为异步任务口径 | R5/R13【确认】 |
| P2 | **到达时间定案、只进不改**：日切快照与已计费事件不回溯修改；一切修正通过调整单（红冲/蓝补）前向追加 | R5/R21/R28【确认】 |
| P3 | **资金变动入口唯一**：余额与权益余量只能经 充值 / 抵扣流水 / 调整单 三条路径变动，杜绝旁路 | R41【确认】 |
| P4 | **判重前置**：双保险判重在受理入口完成，重复流量不进入计价抵扣链 | R3/R4【确认】 |
| P5 | **权限与审计横切**：所有写操作过 M11 权限矩阵；敏感操作强制留痕，两级审批岗位约束（初审≠复审）在服务层强制执行 | 6.2/R29【确认】 |
| P6 | **停服判定实时驱动**：余额变动即时驱动分级停服状态；停服在计量入口生效（拒收），而非事后拦截 | R8/R22/R23【确认】 |
| P7 | **同租户串行强一致**：同一租户的计价抵扣串行执行（余额/余量不超扣）；跨租户无此约束；异步任务（对账/出账）容忍分钟级延迟 | 3.5/R43【确认】 |

### 1.3 模块协作口径（同步 / 异步边界）

| 协作 | 模块 | 时效口径 |
|---|---|---|
| 同步 | M2→M3→M4→M5（受理判重计价抵扣）；M8 停服判定与恢复；两级审批操作 | 实时（事件受理 P99<1s，恢复即时 R23） |
| 异步 | 日切快照、月末出账、每日对账、支付超时释放（分钟级 R43）、资源包到期提醒、审计归档 | 分钟级任务窗口【确认】 |
| 事件联动 | M12 通知（欠费/到期/出账/争议/审核结果）、M13 看板刷新 | 准实时（随触发即时产生，展示无时效承诺） |

## 2. 模块部署关系（逻辑）

> 仅描述职责放置；进程/服务拆分已在 03 v2.0（DT-6 微服务方向）确定：**网关 + platform / billing / equity / finance 四服务**，本节职责放置与之一致。

- **计量接收入口**（M3 的前置部分）：独立承接业务系统上报，具备判重与幂等应答能力，是唯一对外的事件通道；
- **计费核心**（M3 处理段 + M4 + M5）：同步链，按租户串行；
- **任务域**：日切、出账、对账、超时释放、到期提醒、审计归档——统一归入异步任务口径，具备 R42 的告警与重跑幂等要求；
- **审批工作台**（M7/M10 共用 M11 的两级审批约束）；
- **查询与汇聚**：控制台/后台查询、M13 看板，均为只读路径，不侵入计费热路径。

### 3.3 聚合根划分【建议】

租户、产品、订单、资源包实例、账单、调整单、差错单、争议工单。
（聚合内强一致：如"订单+其锁定的库存变动"、"账单+其分段与调整合计"；跨聚合经业务事件联动。）

### 3.4 关键业务不变量（规则落点）

| # | 不变量 | 规则 |
|---|---|---|
| I1 | (上报系统, 事件ID) 全局唯一；(租户, 产品, 业务流水号) 指纹兜底唯一 | R3 |
| I2 | 抵扣链顺序固定：赠送→内置→资源包→余额，不可跳过、不可回退 | R13/A1/A2 |
| I3 | 任意时刻 余额 ≥ 透支阈值；抵扣后各抵扣源余量 ≥ 0 | R16/R22 |
| I4 | 账单应付 = 原额 + Σ(生效调整单金额)；原始账单金额不可变 | R19/R21 |
| I5 | 库存：已售 + 锁定 ≤ 总库存；每人已购（含待支付）≤ 限购 | R31/R32 |
| I6 | 调整单：初审人 ≠ 复审人；生效前必须两级通过 | R29 |
| I7 | 计价金额 = Σ 各指标分段计价，逐笔 4 位小数、汇总 2 位四舍五入 | 3.9/R39 |
| I8 | 停服租户的事件必须被拒收并返回停服错误码 | R8/R22 |
| I9 | 账期内每笔事件记录的适用版本 = 其到达时刻的最新生效版本 | R11 |

## 4. 业务事件清单（驱动联动与通知）

| 业务事件 | 触发方 | 联动 |
|---|---|---|
| 事件已受理 / 重复幂等返回 | M3 | 计费链路；重复事件回执首次结果 |
| 计费完成（含抵扣链分解） | M5 | 抵扣流水、看板 |
| 余额转负（预警）/ 达透支阈值（全停）/ 回正恢复 | M8 | 停服联动 M3、通知 M12、租户状态 M1 |
| 日切完成 | M6 | 快照定案、触发 M7 对账 |
| 账单已出账 / 已确认 / 已结清 | M6 | 通知 M12、争议窗口（R44） |
| 调整单初审通过 / 复审生效 / 驳回 | M7 | 回写账单/账户、审计、通知 |
| 差错单创建 / 已冲正 / 转人工 | M7 | 审计、看板 |
| 订单待支付 / 已支付 / 超时释放 | M9 | 库存回滚、通知、实例发放 |
| 资源包到期提醒（7/3/1 天）/ 已耗尽 / 已过期 | M9 | 通知 M12、留痕 |
| 争议受理 / 超时升级 / 已解决 | M10 | 补偿单、通知 |
| 赠送额度发放 / 到账 | M5/M10 | 通知、审计 |

> **承载说明（03 v2.0 适配）**：以上业务事件由 RocketMQ 主题承载——计费完成/余额变动（billing→finance·platform）、订单已支付（equity→billing）、审计日志（各服务→platform 入 ES）；事件契约（主题、payload、幂等键）在 04 阶段定义。

## 5. 关键设计决策记录（业务级，ADR-lite）

| # | 决策 | 理由 | 备选与取舍 |
|---|---|---|---|
| AD1 | 事件"只进不改"，修正一律走调整单前向追加 | 与实时逐笔计费、日切定案自洽；避免回溯重算的复杂度与对账混乱 | 事件时间回溯重算：准确但复杂度高，已否（R5） |
| AD2 | 抵扣流水采用"主流水 + 来源明细"两级结构 | 一笔事件可解释到每个抵扣源；对账可按来源聚合 | 单层流水：省事但跨源对账困难 |
| AD3 | 停服状态由余额实时驱动，拒收在计量入口生效 | 拦截在最早环节，避免"停服后仍计费"的差错源 | 调用时校验（依赖调用方）：不可靠，已否 |
| AD4 | 两级审批作为通用能力（M11 约束），冲正/补偿/赠送复用 | 规则一致、留痕统一 | 各模块自建审批：重复且易不一致 |
| AD5 | 超时释放按"分钟级任务窗口"定义时效 | 与 R43 一致；对高并发抢购语义完整（支付以状态为准） | 实时逐秒释放：成本高、收益低 |
| AD6 | 看板/查询全部走只读汇聚路径 | 保障计费热路径不受分析型查询干扰 | 混用：有拖慢热路径风险 |
