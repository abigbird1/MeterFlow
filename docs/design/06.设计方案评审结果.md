## 2. 架构合理性检查

| 原则 | 评审结论 |
|---|---|
| P1 热路径唯一且同步 | ✅ 受理→判重→计价→抵扣内聚 billing-service，网关一跳到达（03 §2.5 时序） |
| P2 事件只进不改 | ✅ 事件/流水 append-only 分表；修正走调整单；SQL 无 UPDATE 历史计费数据的路径 |
| P3 资金入口唯一 | ✅ 余额/余量写路径收敛 billing；/feign 仅只读（05 §7）；跨服务经 MQ 事件 |
| P4 判重前置 | ✅ Redis SETNX + 分表唯一索引兜底，边界已声明（04 §2） |
| P5 权限审计横切 | ✅ 审计经 T_AUDIT_LOG 汇聚入 ES；两级审批岗位约束在服务层 |
| P6 停服入口生效 | ✅ 停服状态 Redis + ingest 拒收（BIL-4031） |
| P7 同租户串行强一致 | ✅ billing 单库行锁；跨服务无强一致依赖（最终一致由 M7 兜底） |

服务拆分 S1–S5 与 13 个模块映射无冲突；未发现跨服务热路径 RPC；本地消息表 + 幂等消费 + 对账兜底的最终一致闭环成立。

## 3. 数据库与接口一致性检查

- 05 全部 89 个接口的出入参字段与 04 表结构比对：业务号（bill_no/order_no/adj_no/dispute_no/grant_no/pay_no/err_no）、状态机取值、金额单位（*_cents 分 + 过程金额字符串）一致；
- 抵扣链出参结构与 D2 两级流水（主流水+来源明细）一致；
- **金额单位无一例以浮点数返回**（Q-B 口径遵守）；
- MQ 主题契约（04 §7）与 02 §4 业务事件清单比对：发现 **P-2 缺口**（账单/争议生命周期联动无主题承载），已补充。

## 4. 规范与约束检查

- docs/rules/database-rules.md §1–§7 逐条复核：命名/雪花 ID/必备字段/金额策略/索引数/分表/JSON 边界/删除策略 ✅；
- **物理外键为零**：四库无 FOREIGN KEY，跨库业务号逻辑关联——已将该校验显式成文为规范条款（P-3）；
- meterflow.md #5/#6/#7 与设计文档无冲突；#7 的金额/分页/幂等约定在 05 全部落实；
- 历史裁决回溯：DT-1~DT-6、ET1–ET4、AF1–AF3 在后续文档中均未被违反（AF2/AF3 反向驱动了 04/01 的同步更新）。
